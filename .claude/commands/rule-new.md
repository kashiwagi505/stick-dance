# 繰り返している指示を仕組みに上げる

同じ指示を人が打ち直している状態をやめる。ただし**書くだけでは守られない**ため、検査方法を決めてから書く。

正本: [コマンド・スキル利用ガイド](../../ドキュメント/基準書/コマンド・スキル利用ガイド.md)、[暫定ルール](../../ドキュメント/基準書/暫定ルール.md)

## 前提（この判断はAIが勝手に行わない）

このコマンドは**人に2問答えてもらうためのもの**。ルールを自動生成しない。理由は次のとおり。

- 恒久か暫定かの判断には「この先どうなる予定か」の知識が必要で、それは人が持っている
- 検査方法をAIが選ぶと、最も書きやすいリマインド型に寄る。**リマインドは実測で効いていない**（approveなしマージ48%、注入型フックは効果不明）
- 守られないルールが増えると「書いても効かない」という学習が起き、後から書いた本気のルールも守られなくなる

## 手順

### 1. 対象を1文にする

`$ARGUMENTS` が空なら、直近で繰り返された指示を `.claude/tmp/prompt-log.jsonl` の `count` が大きいものから提示して選ばせる。

対象を「**誰が・どんなときに・何をする（しない）**」の1文にまとめ、ユーザーに確認する。曖昧な言葉（「量のある」「大きすぎる」「適切に」）が入っていたら、**この時点で数値か明確な条件に置き換える**。置き換えられないなら、守ったか破ったかを判定できないので、ここで止める。

### 2. 問1: 恒久か、暫定か

ユーザーに聞く。**AIが決めない。**

| 答え | 置き場 |
|---|---|
| ずっと正しい | 該当する正本。作業ルールは [AGENTS.md](../../AGENTS.md)、工程横断は `ドキュメント/基準書/`、文書作成は `ドキュメント/AGENTS.md`、エージェント手順は `.agents/` |
| 今だけ正しい | [暫定ルール](../../ドキュメント/基準書/暫定ルール.md) |

暫定を選んだ場合は、あわせて次を決める。決まらなければ書かずに止める。

- **撤回条件**（機械で判定できる形が望ましい。無理なら期限の日付）
- **撤回時にやること**
- **起票Issue**（`/issue-new` で起票する）

### 3. 問2: 守る道は、守らない道より手間か

ユーザーに聞く。ここで必要な仕組みが変わる。

**手間は同じ、または守る方が楽**

正本に1行書くだけで終わり。フックもテストも作らない。

> 根拠: `@Autowired` 禁止（違反0件）、外部CDN禁止（0件）、`Closes #N` 不使用（PR80件中0件）はいずれも散文だけで守られている。

**守る方が手間**

散文では守られないので、ブロックする仕組みを決める。次の順で検討する。

| 順 | 手段 | 具体 |
|---|---|---|
| 1 | 守る道を楽にして、手間の差を消す | コマンド化・既定値の変更・テンプレートの用意 |
| 2 | 成果物で検査してCIで落とす | `eslint.config.js` にルールを追加する（対象ファイルとルールを絞る）、または規約を検査する単体テスト（`src/**/*.test.ts`）を足して `npm run check` で落とす |
| 3 | 進め方なので成果物に残らない → フックで**拒否**する | `.claude/hooks/` に追加し `.claude/settings.json` の `PreToolUse` へ配線。`permissionDecision: deny` を返す |

> 根拠（前案件）: CIで落ちる規約ガードテスト6項目は全遵守された。一方、散文だけで決めた日時取得のルールは**違反が6件残り**、同種7件を指摘しても修正されたのは1件だけだった。

**1〜3のどれも決まらない場合は、ルールを書かずに止める。** 「検査できないルールを1本足す」のは、守られないルールを増やすだけ。その旨をユーザーに伝え、指示は口頭で続けるか、条件を変えて手間を消せないかを一緒に考える。

**リマインドだけの仕組みは作らない。**

### 4. 書く

決まった置き場へ書き、同じ変更で連動更新する。

- フック・コマンドを追加した場合: [コマンド・スキル利用ガイド](../../ドキュメント/基準書/コマンド・スキル利用ガイド.md) の該当一覧（**人間向け一覧の唯一の置き場**）、[エージェント・スキル設計基準書](../../ドキュメント/基準書/エージェント・スキル設計基準書.md) の連動更新に従う
- フックで担保するルールは、**フックの無いCodexでも効くよう**ルート `AGENTS.md` か該当正本に同じルールを明文化する（設計基準書「正本と入口」）
- テストを追加した場合: `npm run check` の成功を確認する

### 5. 動くことを確かめる

作ったものが実際に効くかを、その場で確認する。**確認せずに終わらない。**

- テスト: 違反を含む状態で落ち、違反のない状態で通ることを確認する
- フック: 疑似的な入力JSONを標準入力から流し、`deny` が返ることと、対象外のケースで返らないことを確認する
- 散文だけの場合: 確認は不要（手間が同じなので守られる前提）

### 6. 報告する

- 書いた1文と置き場
- 恒久／暫定（暫定なら撤回条件・Issue番号）
- 決めた検査方法と、その動作確認の結果
- 書かずに止めた場合は、その理由と代わりにどうするか

## 終わり方

書いたファイルを**パス指定で**コミットして終了する（`git commit -- <パス> -m "..."`）。PRは `/create-pr` で作る。
