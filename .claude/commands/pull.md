# master を取り込む

本体ツリーの `dev/自分の名前` に `master` の最新を取り込む。[Git運用手順](../../ドキュメント/基準書/Git運用手順.md)「2. 日々の作業の流れ」①の手順そのもの。

**このコマンドを人が打たなくても、本体ツリーのセッションは開始時に未取り込みがあれば取り込む**（正本①、`session-start` フックが件数を知らせる）。このコマンドは、セッション中に master が進んだときや、人が明示的に取り込みたいときの入口。

## 対象と対象外

- **対象**: 本体ツリー（`git worktree list` の1行目）で `dev/自分の名前` をチェックアウトしているセッション。
- **対象外**: 作業ツリーにいるセッション。作業ツリーへ最新を入れるのは `dev/自分の名前` からの取り込みで、`/worktree-end` が行う（master から直接入れない）。作業ツリーで呼ばれたら、その旨を報告して停止する。

## 手順

### 1. 取り込める状態か確認する

```powershell
git worktree list
git rev-parse --abbrev-ref HEAD
git status --short
```

- ブランチが `dev/自分の名前` でなければ停止して報告する（`master` や作業ブランチのままでは取り込まない）。
- **未コミットの変更があれば停止する。** 本体ツリーは編集しない決まりなので、変更が残っていること自体が事故のサイン。誰の変更かをユーザーに確認する（`git stash` は使わない）。ただし改行コードだけの差分（`git diff --numstat` に行が出ない）はマージの妨げにならないので、そのまま進めてよい。

### 2. 未取り込みの件数を見る

```powershell
git fetch origin
git rev-list --left-right --count dev/自分の名前...origin/master
git log --oneline dev/自分の名前..origin/master
```

右側が0なら取り込むものが無い。その旨を報告して終了する（マージコミットを作らない）。

### 3. 取り込む

```powershell
git merge origin/master
```

**コンフリクトが出たら、どちらを採るかを勝手に決めない。** 次の順で進める。

1. `git diff --name-only --diff-filter=U` で対象を出し、1件ずつ両側の内容を読む。
2. **選択肢が1つしかないものは、そのまま解消して報告に回す。** 「片側が起票直後の空欄・もう片側が記入済み」「片側が旧い値・もう片側がリポジトリ全体の付け替え後の値」のように、履歴（`git log -- <パス>`）を見れば新しい意図が一方に確定するもの。何を採ったかは手順5で必ず報告する。
3. **それ以外は、対象ごとに両側の内容と解消案を示してユーザーに決めてもらう。** 両側が別々の内容を足している場合は「両方を残す」が候補になる。
4. 解消したら `git add -- <パス>` でステージし、`git diff --name-only --diff-filter=U` が空になったことと、コンフリクトマーカー（`<<<<<<<`・`=======`・`>>>>>>>`）が残っていないことを確認する。
5. `git commit --no-edit` でマージコミットを作る（**コンフリクト解消中は index 全体を対象にするのが正しく、`safe-commit-guard` もこの場合だけパス指定なしを許可する**）。

**マージの途中のままセッションを終えない。** 判断がつかず続けられないときは `git merge --abort` で取り込み前へ戻し、何が決まらないのかを報告する。

### 4. push する

```powershell
git push origin dev/自分の名前
git rev-list --left-right --count dev/自分の名前...origin/master
```

右側が0になっていることを確認する。

## 終わり方

次を報告する。

- 取り込んだコミット数（無ければ「取り込むものなし」）
- コンフリクトがあった場合は、**対象ファイル・両側が何だったか・どちらを採ったか・その理由**
- push 後の `dev/自分の名前` が master より何コミット先行しているか（＝まだPRに出していない分。溜まっていれば `/create-pr` を提案する）
