# 作業ツリーを作って移る

ファイルを編集する作業は、本体ツリーではなく専用の作業ツリーで行う。本体ツリーは `dev/自分の名前` を集める・PRを出すための場所で、編集しない（`worktree-guard` フックが拒否する）。このコマンドは、作業1件ぶんのツリーと作業ブランチを用意してセッションをそこへ移す。

正本: [Git運用手順](../../ドキュメント/基準書/Git運用手順.md)「2. 日々の作業の流れ」②、「4. 並行作業（複数セッション）」

## 対象と対象外

- **対象**: ファイル編集を伴う作業の開始時すべて。他のセッションがいるかどうかは関係ない。
- **対象外**: `WBS/` 配下だけを触る作業（`/wbs-push` がパス指定でmasterへ反映するため分離不要）。すでに作業ツリーにいるセッション。

## 軽量版とフル版

用意するものは作業の中身で2段階に分かれる。**軽量版を既定とする。**

| 作業の中身                                                                      | 手順                    |
| ------------------------------------------------------------------------------- | ----------------------- |
| ドキュメント・設計書・モックアップ・WBSだけ                                     | 1〜3、5、6（**軽量版**） |
| `src/`・`e2e/`・`index.html`・`package.json`／`package-lock.json`・`tsconfig.json`・`vite.config.ts`・`eslint.config.js` を触る（アプリを起動する／E2Eを回す） | 1〜6（**フル版**）      |

手順4（`.env` とポートの分離）は実装を触るときだけ要る。**判断がつかないときは軽量版で始め、実装を触ることになった時点で手順4だけ追加する。**

## 手順

### 1. 前提を確認する

```powershell
git worktree list
git status --short
git rev-parse --abbrev-ref HEAD
```

- **すでに作業ツリーにいる**（`git worktree list` の1行目＝本体ツリーとカレントが違う）なら、何もせず「分離済み」と報告して終了する。
- 本体ツリーのブランチが `dev/自分の名前` でない場合は、どのブランチから切るかをユーザーに確認する。作業ブランチは `dev/自分の名前` から切るのが既定。
- **本体ツリーに未コミットの変更がある**場合は手順2へ。無ければ手順3へ。

### 2. 本体ツリーの未コミット変更を退避する（ある場合だけ）

本体ツリーは編集しない決まりなので、変更が残っていること自体が異常。`git status --short` を見せ、誰の変更かをユーザーに確認する。`git stash` は使わない（他セッションの未コミット変更まで巻き上げた事故があるため。本体ツリーでは `safe-commit-guard` フックが拒否する）。

自分の変更だと分かった場合だけ、次のどちらかで持ち出す。

```powershell
# a. 区切りが良いなら、手順3のあと作業ツリー側でパス指定コミットする（推奨。本体ツリーでコミットしない）
git diff -- <自分のファイル...> > "$env:TEMP\wt-carry.patch"
git checkout -- <自分のファイル...>

# b. 追跡されていない新規ファイルは、作業ツリーへ移動する（手順3のあと）
Move-Item <新規ファイル> "$wt\<同じ相対パス>"
```

手順5のあとに新ツリーで `git apply "$env:TEMP\wt-carry.patch"` を実行する。他人の変更なら触らず、その旨を報告して停止する。

### 3. ツリーと作業ブランチを作る

作業名は引数 `$ARGUMENTS`。省略された場合はユーザーに聞く。ブランチ名は `dev/自分の名前-作業名`（例: `dev/yamada-scr14-impl`）。

**同じブランチを2つのツリーで同時にチェックアウトできない**ため、必ず新しい作業ブランチを切る。分岐元は `dev/自分の名前`（`master` から切らない。完了済みで master 未反映の自分の変更を取りこぼすため）。

置き場所は `.claude/worktrees/<作業名>`（本体ツリーのルートからの相対パス）。**ここから外れた場所に作ってはいけない。** Claude Code は `.claude/worktrees/` の外へセッションを移すとき、作業ディレクトリ・書き込み権限・`CLAUDE.md` や設定の読み込み元ごと移ることになるため「permission-root relocation」の確認を毎回出す。この確認は `EnterWorktree` の許可ルールでも「今後も許可」でも抑制できない。リポジトリ配下だが `.gitignore` に `.claude/worktrees/` があるので追跡対象にはならない。同名のディレクトリが残っていたら（前回の片付け失敗の残骸）、`git worktree list` に載っていないことを確認してから削除する。

```powershell
$wt = ".claude\worktrees\<作業名>"
git worktree add $wt -b dev/自分の名前-<作業名> dev/自分の名前
```

**ドキュメントだけの作業ならここで手順5へ進む（軽量版）。**

### 4. `.env` を用意し、必要ならポートを分ける（実装を触るときだけ）

`src/`・`e2e/`・`index.html`・`package.json`／`package-lock.json`・`tsconfig.json`・`vite.config.ts`・`eslint.config.js` を触る場合だけ実行する。

棒人間ダンシングはDBも外部サービスのモックも使わないので、作業ツリーごとに分ける資源は**アプリ（Vite）の待受ポート `SERVER_PORT` だけ**。E2EはPlaywrightが `npm run dev` で自分のポートにアプリを起動し（別ツリーのサーバーを再利用しない）、`vite.config.ts` は `strictPort` のため、2つのツリーが同じポートを使うと後から起動した側が失敗する。

まず本体の `.env` を複製する。

```powershell
Copy-Item .env "$wt\.env"
```

次に、**実装を触る作業ツリーが自分だけか**を見る。`git worktree list` の本体以外のツリーで `.env` を持つものを数える。

```powershell
git worktree list --porcelain | Select-String '^worktree ' | ForEach-Object { $_.Line.Substring(9) } |
  Where-Object { $_ -ne (git worktree list --porcelain | Select-String '^worktree ' | Select-Object -First 1).Line.Substring(9) } |
  Where-Object { Test-Path (Join-Path $_ '.env') }
```

- **自分のツリーだけ**なら、`.env` は複製のまま使う（`.env.example` の既定値）。本体ツリーはアプリを起動しないのでぶつからない。ここで手順5へ。
- **他にもある**なら、`SERVER_PORT` を分ける。他のツリーの `.env` に書かれた番号と重ならず、実際に使われていない番号を選ぶ（ツリーの件数から決めない。片付け忘れの残骸で番号がずれる）。

```powershell
# 空きポート: 既定+1 から順に、他ツリーの .env と重ならず、使われていない番号を選ぶ
netstat -ano | Select-String ":5001\s"
# $wt\.env を書き換える（無ければ追記する）
#   SERVER_PORT=5001
```

> サーバーを持たない作りなので（→ [アプリケーション実装方針](../../ドキュメント/基準書/アプリケーション実装方針.md) 8章）、分けるポートが増える予定は無い。`.env` に秘密値は入らない。

> **`.env` の書き換えに PowerShell の `Get-Content`／`Set-Content` を使わない。** `.env` はUTF-8の日本語コメントを含み、`Get-Content` は既定でシステムのANSIコードページとして読むため、書き戻すと全体が文字化けし行も結合される。壊れても起動時に気付けず、後から別の形で表面化する。`sed -i 's|^SERVER_PORT=.*|SERVER_PORT=5001|' "$wt/.env"` のようにBash（sed）で書き換え、無ければ `printf` で追記する。壊した場合は本体からコピーし直す。

作業ツリーには `node_modules` が無い。アプリやE2Eを動かす前に、ツリーのルートで `npm ci`、E2Eを回すなら `npm --prefix e2e ci` を実行する。

### 5. 移る

Claude Code の `EnterWorktree`（`path` に作ったツリーのパス）で移動する。**`path` は絶対パスで渡す**（例: `C:\Users\...\stick-dance\.claude\worktrees\<作業名>`）。移動後に手順2でパッチを退避していれば適用し、パス指定でコミットする。

置き場所が正しければ確認プロンプトは出ない。出た場合はツリーを `.claude/worktrees/` の外に作っている（手順3をやり直す）。

### 6. 報告する

- 作ったツリーのパス、ブランチ名、**軽量版かフル版か**（フル版なら `SERVER_PORT`）
- 退避した変更の扱い（パッチを適用したか）
- 作業が終わったら `/worktree-end` で `dev/自分の名前` へマージしてツリーを消し、続けて `/create-pr` で master へPRを出すこと

## 終わり方

作業ツリーへ移り、上記を報告して終了する。分離できなかった場合（ポートが空かない等）は、**何が原因で分離できないかを報告して止まる**。本体ツリーのまま作業を続けない。
