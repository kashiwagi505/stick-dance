---
description: タスクを起票する
argument-hint: [やること / 担当 / 期日 / 見積 を分かる範囲で]
---

依頼: $ARGUMENTS

[WBS/AGENTS.md](../../WBS/AGENTS.md) の「タスクを起票するとき」に従って
`WBS/タスク/` にファイルを作ってください。要点:

1. **重複チェック** — `WBS/タスク/` を検索し、似たタスクが無いか確認する。
   あれば「既存の◯◯と重複しませんか」と聞いてから進める。
2. **不足情報は聞く** — `owner` / `due` / `estimate` が依頼文から読み取れなければ、
   勝手に決めずユーザーに聞く。`category` は内容から判断してよい。
3. **ファイル名がタスク名** — 内容が分かる日本語にする。`/` `:` `?` `*` は使えない。
4. **プロパティは7つだけ**（owner / status / start / due / estimate / actual / category）。
   増やさない。`status` は `未着手` で作る。
   `category` は次の9つから選ぶ（**頭の番号ごと**書く。他の値を作らない）:
   `1_プロジェクト管理` / `2_AI管理` / `3_要件定義` / `4_基本設計` /
   `5_詳細設計・実装・テスト` / `6_結合テスト観点` / `7_インフラ連携` / `8_システムテスト＋検収` /
   `9_改善`
   どれか判断がつかない場合は候補を2つ挙げて聞く。
5. **「やること・終わったと言える条件」を具体的に書く。** 空のチェックボックスだけにしない。
6. 設計・実装に関わるタスクなら、`ドキュメント/` の**着手前に読む正本**への相対リンクを
   メモ欄に張る。どれを読むかはルート [AGENTS.md](../../AGENTS.md) の表で引く。
7. **負荷チェック** — その担当のその期間の見積合計が1日7hを超えるなら警告する。

複数のタスクをまとめて頼まれた場合は、1件ずつ別ファイルにする。

**マイルストーンを頼まれたとき**（「◯◯確定を8/19に置いて」など）は、
ファイル名の頭を `【MS】` にし、`estimate: 0`、`start` と `due` を同じ日にする。
本文は「## この日までに揃っていること」のチェックリストにする（作業手順ではない）。

作成後、ファイルへのリンクと、設定した担当・期日・見積を1行で報告してください。
コミットはしない（ユーザーが自分のブランチでコード変更と一緒に出す）。
