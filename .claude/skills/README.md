# .claude/skills/ — 外部スキル

品質面（SEO・パフォーマンス・アクセシビリティ）の判断基準をAIに持たせるために、外部のスキル集を取り込んでいる。
自作の手順・スキルの置き方は [エージェント・スキル設計基準書](../../ドキュメント/基準書/エージェント・スキル設計基準書.md) を正本とする。

## 収録しているもの

出所: [addyosmani/web-quality-skills](https://github.com/addyosmani/web-quality-skills)（MIT License、取得日 2026-08-17）

| スキル | 中身 |
|---|---|
| `seo` | title 50〜60文字・meta description 150〜160文字・`<h1>` は1つ、canonical、XMLサイトマップ、JSON-LD（Organization / Product / Breadcrumb 等）、タップ領域48px・フォント16px |
| `performance` | 性能予算（総重量1.5MB・ファーストビュー画像500KB・TTFB 800ms 等）、画像最適化、フォント読み込み、キャッシュ戦略 |
| `core-web-vitals` | LCP / INP / CLS の閾値と改善手順 |
| `accessibility` | WCAG 2.2 準拠のチェックとパターン集 |
| `best-practices` | セキュリティ・互換性・コード品質 |
| `web-quality-audit` | 上記をまとめて監査する統合スキル |

中身はマークダウン（`SKILL.md`）で、**依頼内容が `description` に合致したときClaudeが自動で読み込む**。「SEOを見て」「表示が遅い」のような依頼で発動し、通常の実装作業中には出てこない。

## 使いどころ

棒人間ダンシングはブラウザ1枚の中で HTML の表示を切り替えて動くアプリ（棒人間と舞台は Canvas 2D、ボタン・案内は HTML）で、PCのChromeを基準に GitHub Pages から一般公開する（→ [インフラ要件](../../ドキュメント/01_要件定義/03_インフラ要件.md) I1・I2）。中身の多くは canvas に描くゲームなので、検索エンジン向けの `seo` は公開ページの最低限（タイトルなど）にしか効かない。効くのは、操作から音が鳴るまでの遅れ（N2。プレイ中の描画と入力の処理が音を詰まらせないこと）と、キーボードでの操作のしやすさである。

| 工程 | 使うスキル | 決める・直すもの |
|---|---|---|
| デザインシステム（`ドキュメント/02_基本設計/画面設計/デザインシステム/`）・画面設計・モックアップ | `accessibility` | 文字の大きさ、色以外での状態表現（楽器の違い・分身の人数・鳴った瞬間の光り方。楽器は色で表すので、色だけに頼らない）、キーボードでの操作。数値はこのスキルの既定値ではなくデザインシステム正本の値を優先する。**寸法とマークアップ構造は設計時に確定させる**（後から直すと画面設計書・モックアップ・実装（`src/view/`）・テスト観点表が連動する） |
| 画面の実装（`src/view/`・`index.html`） | `performance`、`best-practices` | プレイ中の描画で主スレッドを長く塞がないこと（INP）、画像の読み込み、外部CDNを参照しないこと |
| 音の遅れ（N2: 操作から音が鳴るまで）の確認 | `performance`、`core-web-vitals` | 遅れの内訳のうち、画面側の処理（入力の受け取り・描画）の分を詰める。測れる形で作ることは実装方針9章のとおり |

## 注意

- **スキルは要件を変えない。** 要件定義に含まれていない改善（SEO・スマホ対応など）は、要件内の作業として正当化できる範囲（音の遅れN2の改善手段など）を超えて実装しない。スマホ向けの調整は、スマホ・タブレット対応を最初の版でやらないと決めているため実装しない（→ [要件定義](../../ドキュメント/01_要件定義/README.md) 3章）。一般公開はするが、構造化データ・sitemap などの検索向けの作り込みは要件に無いため実装しない。デザイン系の数値基準（タップ領域・フォントサイズ等）も同様に、外部スキルの既定値ではなくプロジェクト正本（[デザインシステム](../../ドキュメント/02_基本設計/画面設計/デザインシステム/readme.md)）の値を優先する。
- **設計書を飛ばさない。** スキルの助言で画面の実装を変える場合も、[ドキュメント/AGENTS.md](../../ドキュメント/AGENTS.md) の「連動して更新するもの」に従い、画面設計書・モックアップを同じ変更で更新する。
- `web-quality-audit/scripts/analyze.sh` は bash と `jq` を必要とする。Windows標準環境では動かないため、使う場合は Git Bash と jq を用意する（読み取り専用のHTML静的チェックで、ファイルは変更しない）。

## 更新

```powershell
npx skills add addyosmani/web-quality-skills -g -y   # ~/.agents/skills/ を更新
```

を実行したうえで、`~/.agents/skills/` の各フォルダをこのフォルダへコピーし直す。差分をPRでレビューしてから取り込む。
