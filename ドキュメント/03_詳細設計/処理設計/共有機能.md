## 1. 設計判断

| No | 判断事項 | 採用方針 | 理由・影響 |
|---|---|---|---|
| 1 | URL の形 | `#r=<版>.<中身>`。版は10進の整数（今は `1`）、中身は記録を詰めたバイト列を `CompressionStream('deflate-raw')` で圧縮し、URL でそのまま使える Base64（`-`・`_`、`=` の詰め物なし）にしたもの | 版を圧縮の外に置くので、版が違うことを中身を展開せずに見分けられる。`#` 以降はサーバーに送られない（実装方針8章） |
| 2 | 記録の詰め方（版1） | 先頭から順に: 分身の数 n（1バイト）→ 分身ごとに「周の番号（可変長整数）・楽器の番号 0〜4（1バイト）」→ キー入力の数（可変長整数）→ キー入力ごとに「前の入力からの刻みの差（可変長整数。1つ目は刻み0からの差）・キーと押した／離した（1バイト。下位3ビットがキー W・A・S・D・↑・←・↓・→ の 0〜7、4ビット目が押した=1）」。可変長整数は7ビットずつ下位から並べ、続きがあれば最上位ビットを1にする形 | キー入力は1つあたり多くが2バイトになり、圧縮前でも短い。姿勢は持たない（技術選定 3.1） |
| 3 | 記録に入れる範囲 | 踊り始めから、最後の分身の周の終わりの刻みより前のキー入力だけ（踊り機能 設計判断 No.9）。それより後の入力は捨てる | 鑑賞の計算に要らない入力で URL を伸ばさない |
| 4 | 長さの上限 | `#r=` から終わりまでで **4000 文字**（設定 `DEFAULT_SHARE.maxChars`）。超えるときは URL を作らず「長すぎる」を返す | SNS・チャットに貼れる長さに収める（N4）。5人をふつうに踊った記録は 1000 文字前後に収まる見込みで、上限に届くのは踊らずに何分も消しては踊り直した場合だけ。そのときは SCR03 6章 No.3 を出す |
| 5 | 読み戻しの確かめ | 次をすべて確かめ、1つでも外れたら「壊れている」: 文字が Base64 の範囲、展開できる、バイト列がちょうど終わる（足りない・余るがない）、n が 1〜5、楽器が 0〜4、周の番号が小さい順に重ならない、キーが 0〜7、同じキーを押したまま押す・押していないのに離すがない、最後のキー入力の刻みが最後の分身の周の終わりより前、最後の周の番号が設定 `DEFAULT_SHARE.maxLoop` 以下 | 外から来たデータは受け取った場所で形を確かめる（実装方針9章）。周の番号の上限で、計算し直しが重くなりすぎる URL を止める |
| 6 | 版が違う URL | 版が今の版と違えば（古い・新しいどちらも）「版が違う」を返し、再生しない。古い版を読み替える仕組みは持たない | 実装方針7章・9章（後方互換を持たない）。画面の扱いは SCR04 6章 No.2 |
| 7 | 版を上げるとき | 記録の詰め方、物理の規則や数値（踊り機能）、段・音・パン・楽器の割り当て（音の並び機能）、拍と刻みの対応、テンポ・小節数のどれかを、同じ記録から違う踊りや音になる形で変えたとき。伴奏・音量・音色・画面だけの変更では上げない | 古い URL が黙って別の踊りや音になるのを防ぐ |
| 8 | 失敗の返し方 | 作る・読み戻すとも、例外を投げずに結果（成功の値か、失敗の種類「壊れている」「版が違う」「長すぎる」）を戻り値で返す。展開の中で起きた例外はここで受けて「壊れている」にする | 実装方針5章。画面に内部の詳細を出さない |

## 2. 層ごとの責務

| 層・種類 | この機能での責務 | 主な受け取り・受け渡し |
|---|---|---|
| `src/core/` | 記録の型（キー入力・分身の周と楽器）。記録の範囲を切る（設計判断 No.3） | 記録 |
| `src/share/`（記録 ⇔ URL） | 詰める・圧縮・文字にする・長さの確かめ。逆向きと確かめ（設計判断 No.5）。版番号 | 受け取り: 記録／`#` 以降の文字列。渡す: `#r=...` の文字列／記録、または失敗の種類 |
| `src/view/` | SCR03 で URL を作ってクリップボードへ写す。SCR04 で読み戻しの結果を画面に出す | `share` の結果 |
| `src/main.ts` | ページを開いたときに `#r=` の有無で SCR01 と SCR04 を分ける。「自分も踊る」で `#r=` を消す | URL |

## 3. 重要な処理フロー

1. 作る（SCR03 の見終わったとき）: 記録 → 範囲を切る → 詰める → 圧縮 → 文字にする → `#r=1.` を付ける → 長さを確かめる。成功なら、ページの今の URL の `#` より前に付けて共有URLにする。
2. 読み戻す（SCR04 を開いたとき）: `#r=` 以降を `.` で版と中身に分ける → 版を確かめる → 文字をバイト列へ → 展開 → 読み → 確かめる。成功した記録だけを鑑賞へ渡す。

## 4. 時間・再現性・データの扱い

| 処理 | 対象 | 結果の扱い | 失敗時・遅延時の扱い |
|---|---|---|---|
| 圧縮・展開 | 共有URL | ブラウザ標準の `CompressionStream`・`DecompressionStream`（非同期）。同じ記録からは同じ URL になる（時計・乱数を使わない） | 展開できなければ「壊れている」 |
| 往復 | 記録 | 記録 → URL → 記録 で元と一致する。そこから計算した姿勢の列と音の並びも一致する（N3） | 対象なし |
| 仮の数値 | 設定 | `DEFAULT_SHARE` の `maxChars`・`maxLoop`・`version`は `src/share/settings.ts` | 対象なし |

## 5. エラー・セキュリティ・その他の制御

| 条件・区分 | 検出・実施箇所 | 最終動作 | 補足 |
|---|---|---|---|
| `#r=` 以降が壊れている | `src/share` | 「壊れている」を返す → SCR04 6章 No.1 | 例外を握りつぶさず、戻り値にする |
| 版が違う | `src/share` | 「版が違う」を返す → SCR04 6章 No.2 | 版の部分が整数でなければ「壊れている」 |
| 長すぎる | `src/share` | 「長すぎる」を返す → SCR03 6章 No.3 | |
| 記録の送り先 | 対象なし | 記録をページの外へ送らない。外部の短縮URLサービスも使わない | インフラ要件 I1 |
| クリップボードへの書き込みの失敗 | `src/view` | SCR03 6章 No.2（URL を欄に出して選ぶ） | ブラウザの許可による |
