# 見た目の方向

[デザインシステム](../readme.md) の規定が、なぜその値なのかを残す。規定そのものは readme.md と tokens/ が正本で、本書は理由だけを書く。

## 1. 主役は棒人間と、鳴った瞬間の光

見た目の方向は「夜のステージ（ネオン）」（→ [判断ログ](../../../../01_要件定義/判断ログ.md) D24）。暗い舞台に楽器ごとの色の光を当て、**棒人間と、鳴った瞬間に光る音がいちばん目立つ**ようにする。ほかの要素（ボタン・案内・枠）は照明の白ともやの2色だけで静かにまとめ、主役と光の強さを競わせない。

## 2. 色

- **地は真っ黒ではなく、夜の藍（`#110f1f`）。** 黒地に1色だけ強い差し色を置く見た目はよくある既定の形なので避けた。藍の地は、楽器の5色（暖色と寒色が混ざる）のどれとも濁らずに並ぶ。
- **差し色を1つに決めない。色は楽器の5色だけで、意味は必ず「楽器」。** 1人目の黄をボタンの色にも使うと、「黄＝旋律」と「黄＝押せる」が混ざる。ボタンは照明の白にして、色は楽器の意味だけに取っておく。これで、鑑賞で5人が並んだときに画面の色の数がそのまま人数になる。
- 楽器の5色は試作の色を引き継いだ。遊んだ人が試作と製品で迷わないようにするため。
- エラーの赤を置かないのは、桃（3人目）と見分けにくく、「色＝楽器」を崩すため。失敗は文言と形（破線の枠）で伝える。

## 3. 書体

- **タイトルは Stick（フォントワークス）。** 文字が太さのそろった「棒」の線だけで組まれた書体で、線で描く棒人間と同じ作りをしている。タイトルの文字そのものが棒人間の仲間に見えることを、トップの記憶に残る一点にする。
- 使うのはタイトルの8文字だけ。ほかに使うと「棒」の書体が安くなり、読みやすさも落ちる。8文字だけに切り出して数KBにし、読み込みを待たせない。
- 本文は端末の標準のゴシック。Web フォントにすると日本語は数MBになり、楽器の音の読み込み（数MB）と取り合うため。

## 4. 光と形

- 舞台の上では影は見えないので、浮かせたいものは**光らせる**。光は強いもの（タイトル・鳴った頭・主ボタン）だけに絞る。全部が光ると、鳴った瞬間の光が埋もれる。
- ボタンの両端が丸いのは、ネオン管の端と棒人間の線の端（丸）に合わせるため。角の立ったボタンは舞台の上で浮く。

## 5. 動き

- 曲は 124 BPM なので、飾りの動きも拍（484ms）でそろえる。画面の動きと曲の拍がずれると、音と動きの結びつき（F6）が弱く見える。
- 飾りの動きは少なくする。動いてよいのは、トップでタイトルが点く一瞬と、待っている棒人間が拍に合わせて小さく揺れることだけ。

## 6. 避ける見た目

| 避けるもの | 理由 |
|---|---|
| 遠近の格子の床、マゼンタと水色のグラデーション、金属の文字 | 「ネオン」と言われて真っ先に出てくる 80 年代風の既定。棒人間の線と喧嘩する |
| 黒地＋1色の差し色 | 生成した見た目によくある既定。色の意味（楽器）が出せない |
| 楽器の色のボタン・見出し | 色＝楽器が崩れる（2章） |
| 点滅し続ける光 | 主役の光が埋もれる。光に敏感な人の負担になる |
