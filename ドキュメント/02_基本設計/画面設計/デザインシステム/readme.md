# デザインシステム

棒人間ダンシングの全画面に共通する見た目の正本。画面設計書・モックアップ・実装（`src/view/`・`index.html`）は、配色・書体・余白・形・光・動き・共通部品をここから相対リンクで参照し、転記しない。見た目の方向は [判断ログ](../../../01_要件定義/判断ログ.md) D24（夜のステージ・ネオン）。

| フォルダ・ファイル | 中身 |
|---|---|
| [tokens/tokens.css](tokens/tokens.css) | 実数のトークン（色・書体・文字の大きさ・余白・形・光・動き・表示幅）。モックアップはこのファイルを直接読む |
| [guidelines/見た目の方向.md](guidelines/見た目の方向.md) | 設計意図（なぜこの色・書体・光にしたか）と、避ける見た目 |
| [components/ボタン.md](components/ボタン.md) | 主ボタン・副ボタンの仕様 |
| [components/状態の案内.md](components/状態の案内.md) | 準備中・失敗などを伝える1行の案内の仕様 |
| [components/部品.css](components/部品.css) | 上の部品と、全画面の地・フォーカスの共通スタイル。モックアップはこのファイルを直接読む |
| [fonts/](fonts/) | タイトル書体（Stick を「棒人間ダンシング」の8文字だけに切り出したもの）とライセンス（OFL.txt） |

## 1. 決めごと

### 1.1 対応端末と表示幅

- 対象は PC の Chrome だけ（→ [非機能要件](../../../01_要件定義/02_非機能要件.md) N1）。スマートフォン・タブレット向けのレスポンシブ対応はしない。
- 基準の表示領域は **1280×720**。**1024×640 未満は想定しない**（その場合はスクロールで見られればよい）。
- 舞台（棒人間を描く Canvas）は **960×540**（`--frame-width`・`--frame-height`）。画面の中央に置き、表示領域が広くても拡大しない。舞台の外は地の色（`--color-stage`）で埋める。
- HTML の要素（タイトル・ボタン・案内）は舞台の枠（960×540）の中か、その上下に置く。

### 1.2 色

| トークン | 値 | 使うところ |
|---|---|---|
| `--color-stage` | `#110f1f` | 全画面の地（夜の舞台） |
| `--color-stage-raised` | `#1c1931` | 窓・案内の面 |
| `--color-floor` | `#2e2a4a` | 床の線・区切り・枠 |
| `--color-light` | `#f4f0ff` | 照明の白。本文・棒人間（楽器が決まる前）・主ボタンの地・フォーカス |
| `--color-haze` | `#9d97bb` | 補足の文字・押せない状態 |
| `--color-inst-1`〜`5` | `#ffcf5a` 黄／`#5ad1ff` 水色／`#ff8fc4` 桃／`#8be38b` 緑／`#c9a2ff` 紫 | 楽器（1人目 旋律／2人目 ベース／3人目 和音／4人目 高い旋律／5人目 打楽器。→ [音の設計方針](../../設計方針/音の設計方針.md) 3章） |

- **楽器の色は楽器を表すときだけ使う。** ボタン・見出し・エラーなど UI の飾りに使わない。画面の中で色が付いていれば、それは必ずどれかの楽器を指す。
- **色だけで区別しない。** 楽器は色に加えて名前（「旋律」など）か人の順番を必ずどこかに出す。ただし、読み上げない飾り（`aria-hidden`。例: SCR01 の5つの照明）として5色を並べるときは、名前を出さなくてよい。状態（押せる・押せない・失敗）は色に加えて文言と形（枠の線の種類）で表す。
- エラー専用の色（赤）は置かない。赤系は 3人目（桃）と見分けにくく、「色＝楽器」を崩すため。失敗は [状態の案内](components/状態の案内.md) の形と文言で伝える。
- 文字と地のコントラスト比: `--color-light` / `--color-stage` は約 16.9:1、`--color-haze` / `--color-stage` は約 6.8:1、`--color-haze` / `--color-stage-raised` は約 6.2:1、楽器の5色 / `--color-stage` は 9.0〜12.9:1（いずれも 4.5:1 以上）。
- `--color-floor` は地との比が約 1.4:1 で、飾りの線にだけ使う。押せる・押せないなどの意味を持つ枠には `--color-light` か `--color-haze` を使う。

### 1.3 書体と文字の大きさ

| 役 | 書体 | 大きさ | 使うところ |
|---|---|---|---|
| タイトル | `--font-title`（Stick Title） | `--text-title` 88px | トップのタイトル「棒人間ダンシング」**だけ** |
| 見出し | `--font-body` 太字 | `--text-heading` 28px | 窓・画面の見出し |
| リード・主ボタン | `--font-body` | `--text-lead` 20px | トップの一文、主ボタンの文字 |
| 本文 | `--font-body` | `--text-body` 18px | 案内・説明 |
| 補足 | `--font-body` | `--text-small` 16px | 補足・副ボタン |
| キー名 | `--font-key` | 周りの文字と同じ | WASD・矢印キーなどキーの名前だけ |

- **文字は 16px より小さくしない。** Canvas の中に描く文字（音階・刻みの番号など）も同じ。
- Stick Title は「棒人間ダンシング」の8文字しか入っていない。**ほかの文字列に使わない**（入っていない文字は本文の書体で出てしまう）。タイトルの文字列を変えるときは、[fonts/](fonts/) の切り出しを作り直し、[素材/書体の記録](../../../素材/書体の記録.md) を更新する。
- 本文の書体は端末にある書体を使う（Windows は Yu Gothic UI、Mac はヒラギノ角ゴ）。Web フォントにしない。
- 行間は本文 1.7。

### 1.4 余白と形

- 余白は 4 の倍数（`--space-1` 4px 〜 `--space-8` 64px）だけを使う。
- ボタンは両端を丸くする（`--radius-tube`）。ネオン管の端と、棒人間の線の端（丸）にそろえる。窓・案内の面の角は `--radius-panel` 12px。
- 棒人間の線の太さは舞台 960×540 のとき `--line-figure` 7px。線の端と関節は丸くする。

### 1.5 光

- 舞台では影を使わず、**光で浮かせる**（`--glow-light`・`--glow-soft`）。
- 強い光（`--glow-light`）を使うのは、タイトル・鳴った瞬間の頭・押せる主ボタンにマウスを乗せたとき・フォーカス中の主ボタンだけ。常に光らせる要素を増やさない。

### 1.6 クリック対象とキーボード

- クリック対象は高さ・幅とも **48px 以上**（`--target-min`）。
- すべてのボタンは Tab で順に移れて、Enter と Space で押せる。画面の操作キー（WASD・矢印キー・数字キー・Space）は [各画面設計](../) で決める。
- **フォーカスは必ず見える**: `--focus-ring`（3px の照明の白）を `--focus-offset` 4px 離して出す。`:focus-visible` で出し、マウスで押したときは出さない。

### 1.7 動き

- 動きは**拍（`--beat` 484ms、124 BPM の4分音符1つ）の倍数**でそろえる。照明が点く・消えるときは `--ease-light`。
- 棒人間と音に関わる動き（踊り・鳴った瞬間の光）は遊びの中身なので止めない。それ以外の飾りの動き（タイトルが点く、待っている棒人間が揺れるなど）は、`prefers-reduced-motion: reduce` のとき**止めて最後の状態で出す**。

### 1.8 ページの見出しとブラウザのタブ名

- ブラウザのタブ名は、**どの画面でも `棒人間ダンシング`**。画面はページ遷移せず同じページ内で切り替えるため、画面ごとに変えない。
- `<h1>` はページに1つで、「棒人間ダンシング」とする。トップではタイトルとして見せ、ほかの画面では見た目に出さずに読み上げ用に残す。画面ごとの見出しは `<h2>` から始め、見出しのレベルを飛ばさない。

## 3. 実装への写し方

- 実装（`src/view/`）の CSS は `src/view/styles/` に置く。本書のトークンを写した `tokens.css`、共通部品を写した `components.css`、画面ごとに1ファイル（例: `top.css`）に分ける。値の正本は本フォルダで、実装側で値を変えない。
- タイトル書体（[fonts/](fonts/) の `StickTitle.woff2` と `OFL.txt`）は `public/fonts/` に写して配信する。
- 写した値が本フォルダとずれていないことを、単体テストで確かめる（実装側の `tokens.css` の値と [tokens/tokens.css](tokens/tokens.css) を突き合わせる）。

## 4. 変更の手順

1. 本書（規定の本文）と [tokens/tokens.css](tokens/tokens.css)・[components/部品.css](components/部品.css)（実数）を同じ変更で直す。
2. 影響する画面設計・同名モックアップ・実装（`src/view/`・`src/view/styles/`・`public/fonts/`・`index.html`）・E2E観点表を同じ変更で追従させる（→ [ドキュメント/AGENTS.md](../../../AGENTS.md)「連動して更新するもの」）。
3. PR 本文に、変更した節と影響する成果物を書く。
