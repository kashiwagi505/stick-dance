## 1. ケースの前提

| 前提の記号 | 前提の作り方 |
|---|---|
| P1 | `/` を新しいページで開き、「はじめる」を押し、1周踊って分身を1人残し、Enter で鑑賞へ進む（ブラウザの文脈にクリップボードの読み書きを許可しておく） |
| P2 | P1 のあと、鑑賞が終わって「おわり」が出るまで待つ |
| P3 | P2 と同じだが、クリップボードへの書き込みが失敗するように spec 側で差し替えてから開く |

- 時間は固定しない（テスト方針4-3）。鑑賞は「分身の数＋1」周（1人なら約15秒）。

## 2. 観点表

| ケースID | 観点 | 確認内容 | 前提 | 自動化 |
|---|---|---|---|---|
| SCR03-01 | 初期表示 | 見出し「鑑賞」（読み上げ用）があり、「鑑賞中 — 1 / n 人」が出る。終わるまで「共有URLをコピーする」は出ない | P1 | 済 |
| SCR03-02 | 画面遷移（画面の中） | 最後の周が終わると「おわり」が出て、「共有URLをコピーする」（フォーカスあり）・「もう一度見る」・「コピーしないまま再読み込みすると、この曲は消えます。」が出る | P2 | 済 |
| SCR03-03 | 共有URLの作成 | 「共有URLをコピーする」を押すと「共有URLをコピーしました。チャットやSNSに貼って渡せます。」が出て、クリップボードに `#r=1.` で始まる共有URLが入る | P2 | 済 |
| SCR03-04 | 異常系 | コピーに失敗すると「コピーできませんでした。下の欄のURLを選んでコピーしてください。」が出て、「共有URL」の欄に共有URLが入る | P3 | 済 |
| SCR03-05 | ルールどおりのふるまい | 「もう一度見る」を押すと「おわり」が消え、「鑑賞中 — 1 / n 人」から再生し直す | P2 | 済 |
| SCR03-06 | 画面遷移 | コピーした共有URLを新しいページで開くと、遊ばずに共有を開いた画面（SCR04）が出て、「n人の分身が踊ります」が出る（AC3 の E2E で確かめられる部分） | P2 | 済 |
| SCR03-07 | ルールどおりのふるまい | 鑑賞中に画面が隠れると（spec 側で `visibilitychange` を起こす）「一時停止中」が出て、戻ると消える | P1 | 済 |
| SCR03-08 | 外部通信 | 鑑賞から共有URLのコピーまで、ページと同じサイトの外への通信が起きない（記録をどこへも送らない） | P2 | 済 |

- 共有URLの長さが上限を超えるとき（「この曲は長すぎて共有URLにできませんでした。」）は、上限に届く記録を画面操作で作るのに何十分もかかるため、E2E では確かめず単体テスト（`src/share/share.test.ts`）で「長すぎる」を返すことを確かめる。
- 同じ踊り・同じ音になるか（AC3）は単体テストとシステムテストで確かめる（テスト方針2-1）。
