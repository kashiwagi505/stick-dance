# 未採番のバグ

`/bug-new` が起票したバグを、対応が終わるまで置く場所。番号（`BUG-nnn`）はまだ無い。**番号を付ける前の置き場**で、対応が終わると内容は [02_バグ表.md](../../02_バグ表.md) 3章の表へ転記され、ここのファイルは消える。**修正・確認の記入も、転記されるまではここで行う。**

- ファイル名は `<担当者ローマ字>-<YYYYMMDD>-<HHmmss>.md`（例: `yamada-20260908-193012.md`）。見出しはファイル名と同じ。
- master に入ったあと、`/bug-sync`（kashiwagiだけが実行）が、**対応の終わったもの**（`状態` が `修正済`・`確認済`・`取り下げ`）を検出日→ファイル名の順に採番して3章の表へ転記する。手で番号を付けない。
- `状態` が `未対応`・`対応中` のファイルは採番されず、ここに残り続ける。**このフォルダが、まだ片付いていない不良の一覧になる。**
- 起票時に埋めるのは `検出工程`・`検出日`・`検出者`・`対象`・`事象`・`重要度`・`状態`（`未対応`）の7項目。残りは空欄のまま行だけ置く。`混入工程`・`原因`・`対応内容`・`修正コミット`・`確認日`・`密度計上` は修正時にこのファイルへ書き足す。
- 記入ルールの正本は [02_バグ表.md](../../02_バグ表.md) 2-0・2-1。項目は増やさない。

## 書式

```markdown
# yamada-20260908-193012

| 項目 | 内容 |
|---|---|
| 検出工程 | 結合テスト（人間） |
| 検出日 | 2026-09-08 |
| 検出者 | 山田 |
| 対象 | SCRXX / ○○画面（画面IDは画面一覧の採番に従う） |
| 事象 | （期待結果と実際の結果が分かるように書く） |
| 重要度 | 軽微 |
| 混入工程 |  |
| 原因 |  |
| 対応内容 |  |
| 修正コミット |  |
| 状態 | 未対応 |
| 確認日 |  |
| 密度計上 |  |
| 備考 |  |
```

セル内で縦棒を使うときは `\|` と書く（表の列が割れるため）。
