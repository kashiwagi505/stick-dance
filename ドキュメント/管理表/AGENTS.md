# 管理表/ 配下の編集ルール

このファイルは `ドキュメント/管理表/` 配下の管理表を編集するときのルールの正本。現時点の対象はレビュー指摘表の採番と起票。[品質管理指摘表](品質管理指摘表.md)・予算・工数概算は各ファイル内の記入ルールに従う（いずれも1ファイル運用で、担当者別の分割はしない）。

## レビュー指摘表の採番と起票

[レビュー指摘表.md](レビュー指摘表.md) が唯一の正本。新規指摘は3章の表へ直接追記し、列構成・記入ルール・状態遷移は同ファイル2章に従う。

### 起票

- 起票前に、`対象`・`指摘内容` を本表の全行から検索し、同じ指摘を二重に起票しない。
- 指摘IDは `REV-nnn` の通し番号。**起票直前に本表を再読み込みし、3章の最大番号＋1 を付ける。** 取り下げた番号は再利用しない。
- 同じ表への起票は1件ずつ行い、起票後に本表を再読み込みしてID重複と意図しない変更が無いことを確かめる。

### 並行ブランチで番号が重なったとき

同じ表を複数のブランチが同時に触るため、同じ番号を別の指摘に付けてしまうことがある。**後から `dev/自分の名前` または master へ取り込む側が、自分の行を最大番号＋1へ振り直す。** 先に入った側の番号は変えない。振り直した行は `備考` の末尾へ次の形で当時の番号を残す（コミットメッセージ・PR本文に残る番号から行を引けるようにするため）。

```
／ 採番修正（2026-09-14）: 旧ID `REV-250`。取り込み時に番号が重複したため振り直した。コミットメッセージ・PRに残る `REV-250` は当時の採番
```

衝突を減らすため、起票を含むブランチは溜めずに1日以内に `dev/自分の名前` へ入れ、PRを出す（[Git運用手順](../基準書/Git運用手順.md)「3. こまめに取り込む習慣」）。

### 検査

`node .github/scripts/review-table.mjs check` が、本表のIDが `REV-nnn` 形式で重複しないことを検査する。PR作成時に [ci.yml](../../.github/workflows/ci.yml) が実行し、違反があればPRのチェックが失敗する。

## 経緯: 担当者別の作業ファイルは試して廃止した

前案件で、本表が肥大化して同時編集が難しくなったため、担当者別の作業ファイルで起票し確定行だけ本表へ移す分割運用を試した。約2週間で全行を本表へ移して廃止した。**表は1つに保ち、番号が重なったら後から取り込む側が振り直す**（上記「採番」）。
