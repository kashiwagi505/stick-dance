# 02 非機能要件

| ID | 要件 |
|---|---|
| N1 動作環境 | PCの Chrome 最新版を基準にする。Edge・Firefox・Safari をどこまで保証するかは基本設計で決める（→ 判断ログ D11） |
| N2 音の遅れ | キーを押してから音が鳴るまでの遅れが気にならないこと。音は拍に合わせて鳴るので、許容できる遅れは試作で測って決める |
| N3 再現性 | 共有URLから再生した鑑賞は、元の鑑賞と同じ踊り・同じ音になる（→ D13） |
| N4 URLの長さ | 共有URLが SNS やチャットに貼れる長さに収まる。試作は姿勢を1/60秒ごとに記録しており、そのままでは長すぎる。キー入力だけを記録して動きを再計算する、などを基本設計で決める |
| N5 隠れた画面 | ブラウザの画面が隠れても記録が欠けない（試作では、隠れている間の分身の動きが記録されなかった） |
| N6 保全 | コードと素材は GitHub に push する。vault 外の作業フォルダがフォルダごと消えた前例がある（「アプリ制作の情報をvaultにどこまで入れるか」（secondbrain vault の知識ページ）） |
| N7 素材の権利 | 公開するので、画像生成で作った背景・トップページの絵は、使った道具の規約で公開・商用利用が認められていることを、絵の工程に入る前に確認する。どの画像をいつ何で作ったかを [素材/画像の記録](../素材/画像の記録.md) に残す。音は Web Audio で合成し、外の素材は使わない（→ D15） |
| N8 端末の分担 | 画像生成は自宅Mac（Codex）でしかできない。会社PCで進めるのはコードと設計まで。絵が届くまでは仮の絵で進める（→ D15） |
