# doc-sync-checker — 設計書同期チェック手順書

コード・設定・設計書の片方だけが更新された状態を差分から検出する。連動ルールの正本は [ドキュメント/AGENTS.md](../ドキュメント/AGENTS.md) とする。

## 対象

- 原則は `git status` と `git diff HEAD --name-status` で確認できる全変更。
- ブランチが指定された場合は指定ブランチとの三点差分を対象とする。
- 変更がなければ「チェック対象の変更なし」と報告して終了する。

## 手順

1. 変更ファイル一覧と差分内容を取得する。
2. `ドキュメント/AGENTS.md` の連動更新表を読む。
3. 下記ペアについて、コード側だけ・設計側だけの両方向を確認する。
4. 両方が変更されていても内容・件数・名称・URLが一致するか確認する。
5. 指定形式で報告する。

## チェックする連動ペア

| 変更 | 連動先 |
|---|---|
| `src/share` の共有URLの形式（記録の詰め方・版番号・圧縮） | 共有の処理設計、`基準書/アプリケーション実装方針.md` 7章、技術選定 3.1、単体テスト。同じ記録から違う踊りや音になる変更なら版番号 |
| `src/view` の画面の追加・削除・切り替え条件 | `02_基本設計/01_画面一覧・遷移図.md`、画面設計、同名モックアップ |
| `src/view` の画面の表示項目・操作・文言定義、`index.html` | 画面設計、同名モックアップ、E2E観点表 |
| 画面のCSS・モックアップの共通外観変更 | `02_基本設計/画面設計/デザインシステム/`（正本）、画面設計、E2E観点表 |
| デザインシステムの共通デザイン規定変更 | 影響する画面設計・同名モックアップ・`src/view` の描画とCSS・E2E観点表 |
| `src/core` の踊り（物理）・ループ・分身のルール、記録の項目、仮の数値の設定 | `01_要件定義/01_機能要件.md`（F1・F3・F4）、技術選定 3.1、該当処理設計、単体テスト。同じ記録から違う踊りになる変更なら共有URLの版番号（実装方針7章） |
| `src/music` の音の決め方（頭の高さと音階の段・鳴る拍・楽器ごとの段の使い方・伴奏）、テンポ・ループの長さ | 機能要件（F2・F3・F5）、`02_基本設計/設計方針/音の設計方針.md`、該当処理設計、単体テスト、共有URLの版番号（実装方針7章） |
| `src/audio` の楽器・伴奏の音、楽器の音のファイルの追加・差し替え | `02_基本設計/設計方針/音の設計方針.md`、`素材/音の記録.md`。CC BY の素材ならゲーム内のクレジット（F10） |
| 層の追加・読んでよい層の変更 | `02_基本設計/設計方針/技術選定の設計方針.md` 2章、`基準書/アプリケーション実装方針.md` 2章 |
| 新しいモジュールや機能の追加 | 機能要件、処理設計、テスト仕様 |
| `package.json` のスクリプト、`vite.config.ts`（`base` を含む）、公開用の GitHub Actions などの設定・起動方法・配信 | `README.md`、`01_要件定義/03_インフラ要件.md` |
| 画像の追加・差し替え | `素材/画像の記録.md` の生成元と規約確認の記録（非機能要件 N7、実装方針7章） |
| 使う技術・ライブラリの追加・変更 | `02_基本設計/設計方針/技術選定の設計方針.md` 1章、`01_要件定義/判断ログ.md` |

画面設計とモックアップは1画面1セットとする。軽微な文言・スタイル修正で外部仕様が変わらない場合は連動不要としてよいが、判断できなければ「要確認」とする。

デザインシステム（`02_基本設計/画面設計/デザインシステム/`）の変更はGit差分に現れるため、差分そのものを正として連動先を確認する。

## 出力形式

```text
### 乖離N: <一言サマリ>
- 変更されたもの: <ファイルと変更要旨>
- 未更新の可能性: <設計書・設定・コード>
- 根拠: <連動ルールと差分の事実>
- 判定: 乖離 | 要確認
```

- 乖離ゼロなら「**設計書との乖離なし**」と明言する。
- チェックのみを行い、依頼されていない修正はしない。
